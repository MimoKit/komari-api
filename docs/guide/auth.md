# 鉴权与可见性

API 的数据可见性由调用者身份决定，与控制台的访客视角保持一致。

## 身份判定

一次请求按以下顺序判定身份，命中即停：

| 优先级 | 身份 | 判定方式 | 可见范围 |
| --- | --- | --- | --- |
| 1 | 面板管理员 | 登录会话 Cookie | 完整数据，含隐藏节点 |
| 2 | 面板 API Key | `Authorization: Bearer <面板APIKey>` | 完整数据，含隐藏节点 |
| 3 | 插件令牌 | `Authorization: Bearer <令牌>` / `X-API-Token: <令牌>` / `?token=<令牌>` | 完整数据，含隐藏节点 |
| 4 | 匿名访客 | 以上均未命中 | 访客视角 |

访客视角的规则：

- 隐藏节点不可见 —— 列表不返回，详情返回 `404`，不会泄露存在性
- IPv4 / IPv6、备注、Agent 版本为空
- 只返回公开备注（`public_remark`）

## 敏感字段

Agent 上报令牌（`token`）是节点的核心凭据。本插件对所有数据做**字段白名单**投影，令牌无论以何种身份调用都不会出现在响应里。

## 跨域（CORS）

浏览器跨域调用分两层：

1. **面板自身的 CORS 校验**（默认开启）：携带 `Authorization` 的预检请求会直接放行；不携带的跨域请求按面板设置的来源白名单处理
2. **插件的补充开关**：面板关闭 CORS 校验时，插件为所有响应追加 `Access-Control-Allow-Origin: *`

纯服务端调用（机器人插件、脚本）不受 CORS 影响。

## 最佳实践

- 为每个消费方（每只机器人、每个面板）发放独立令牌，泄露时单独吊销
- 令牌只保存在服务端，不要打包进客户端
- 需要隐藏节点的数据时，用令牌调取，不要为了方便把节点设为可见
